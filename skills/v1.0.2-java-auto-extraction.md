# 视频转素材平台 — Java 上传自动提取与任务管理改造

## 一、项目背景

`video-asset-server`

- Spring Cloud 2025.0.x
- Spring Cloud Alibaba
- MyBatis-Plus
- MySQL
- Redis

后端主要模块：

请先检查当前仓库实际结构，不能假定所有模块都已经实现。

## 二、本轮开发目标

重构现有视频上传与素材提取流程。

原流程：

```text
上传视频
    ↓
进入素材库
    ↓
点击分镜提取
    ↓
点击人物提取
    ↓
查看素材
```

目标流程：

```text
上传视频
    ↓
选择自动提取及类型
    ↓
确认上传
    ↓
保存视频
    ↓
自动创建 AI 提取任务
    ↓
后台异步执行
    ↓
保存提取结果
    ↓
任务中心查询进度
    ↓
素材库查看结果
```

**素材库不再承担任务触发职责。**

## 三、统一提取类型

创建统一枚举：

```java
public enum ExtractionType {

    SHOT,

    CHARACTER,

    DIALOGUE,

    BACKGROUND,

    AUDIO,

    STORY
}
```

对应含义：

| 类型 | 功能 |
|---|---|
| SHOT | 分镜检测、关键帧 |
| CHARACTER | 人物检测、人物素材 |
| DIALOGUE | 台词、说话人、时间戳 |
| BACKGROUND | 背景提取 |
| AUDIO | 音频提取与分类 |
| STORY | 剧情事件分析 |

目前优先复用 Python 已实现的分镜与人物提取能力。

其余能力如果 Python 尚未实现，应标记为不支持，不允许伪造任务完成。

## 五、视频上传接口改造

目标接口：

```http
POST /api/media/videos/upload
```

请求：

`multipart/form-data`

字段：

```text
file
projectId
episodeNumber
autoExtract
extractTypes
```

其中 `extractTypes` 支持多个提取类型。

### 业务要求

1. 校验用户登录状态。
2. 校验项目归属权限。
3. 校验视频格式和文件大小。
4. 防止重复提交。
5. 将视频保存至 MinIO。
6. 创建或关联剧集记录。
7. 保存视频元数据。
8. 根据 `autoExtract` 决定是否创建任务。
9. 上传接口不等待 Python 完成提取。
10. 返回视频 ID、剧集 ID、任务 ID 和任务状态。

### 返回示例

```json
{
  "videoId": 1001,
  "episodeId": 2001,
  "autoExtract": true,
  "taskId": 3001,
  "taskStatus": "PENDING"
}
```

使用项目现有统一 Result 响应结构包装。

### 关闭自动提取

当：

```text
autoExtract = false
```

只保存视频，不创建 AI 任务。

### 开启自动提取

当：

```text
autoExtract = true
```

必须：

1. 校验提取类型不为空。
2. 校验提取类型受支持。
3. 保存视频记录。
4. 创建 AI 任务。
5. 异步投递任务。
6. 返回任务 ID。

如果视频上传成功但任务创建失败，必须保留视频数据，返回明确状态，并支持后续补建任务。

## 六、任务管理接口

统一任务状态：

```java
public enum AiTaskStatus {

    PENDING,

    RUNNING,

    SUCCESS,

    PARTIAL_SUCCESS,

    FAILED,

    CANCELLED
}
```

新增或适配以下接口：

```http
POST /api/ai/tasks

GET /api/ai/tasks

GET /api/ai/tasks/{taskId}

GET /api/ai/tasks/{taskId}/steps

POST /api/ai/tasks/{taskId}/retry
```

### 创建任务

请求示例：

```json
{
  "episodeId": 2001,
  "extractTypes": [
    "SHOT",
    "CHARACTER"
  ]
}
```

要求：

- 验证用户权限。
- 验证视频存在。
- 验证提取能力。
- 防止重复创建相同任务。
- 保存任务记录。
- 异步发送执行消息。

### 任务列表

支持：

- projectId
- episodeId
- status
- pageNum
- pageSize

返回分页数据。

### 任务详情

至少包含：

```json
{
  "taskId": 3001,
  "episodeId": 2001,
  "status": "RUNNING",
  "progress": 50,
  "createdAt": "2026-11-20T15:00:00+08:00",
  "startedAt": "2026-11-20T15:01:00+08:00",
  "finishedAt": null,
  "steps": [
    {
      "type": "SHOT",
      "status": "SUCCESS",
      "progress": 100
    },
    {
      "type": "CHARACTER",
      "status": "RUNNING",
      "progress": 30
    }
  ]
}
```

进度必须来自真实处理结果或真实阶段事件。

没有进度数据时允许返回 null，不能伪造百分比。

## 七、任务执行机制

采用：

**Java AI 服务 + RabbitMQ + Python FastAPI**

流程：

```text
Media 上传完成
      ↓
AI Service 创建任务
      ↓
MySQL 保存任务
      ↓
RabbitMQ 投递消息
      ↓
AI 调度组件
      ↓
Python FastAPI
      ↓
执行素材提取
      ↓
回传任务结果
      ↓
Java 更新任务状态
      ↓
Media 保存素材元数据
```

要求：

1. 使用可靠的消息投递机制。
2. 避免数据库事务未提交就发送消息导致任务丢失。
3. 可以采用事务 Outbox 或可靠的任务扫描补偿机制。
4. 消费者必须支持幂等。
5. 不允许同一任务被并发重复执行。
6. Python 调用超时不能直接等同于任务失败。
7. 任务失败记录明确原因。
8. 失败任务支持重试。
9. 服务重启后可以恢复未完成任务。
10. 不允许无限重试。
11. 任务完成后必须保存真实结果。
12. 不能在上传 HTTP 请求中同步等待完整视频解析。

优先复用现有 Java 与 Python 通信代码。

本轮不要擅自修改 Python 项目。

## 八、提取任务与依赖关系

不同提取类型之间可能存在依赖。

例如：

```text
SHOT
  ├── CHARACTER
  ├── BACKGROUND
  └── STORY

AUDIO
  └── DIALOGUE
```

这里的依赖关系是业务规划，不代表现有 Python 已实现所有处理流程。

要求：

- 任务调度支持未来扩展依赖关系。
- 已有分镜结果可以复用。
- 已有音频文件可以复用。
- 不应每次提取人物都重复执行完整视频抽帧。
- 补充提取时只运行必要步骤。
- 不能因为一个提取类型失败就丢失其他成功素材。

对于 Python 当前支持的处理流程，按照实际依赖执行，不要强制套用尚未实现的 DAG 引擎。

## 九、素材库查询接口

素材库只负责查询和管理素材。

新增或适配：

```http
GET /api/media/episodes/{episodeId}/summary

GET /api/media/episodes/{episodeId}/assets
```

查询参数：

```text
type
pageNum
pageSize
```

支持：

- SHOT
- CHARACTER
- DIALOGUE
- BACKGROUND
- AUDIO
- STORY

### 素材摘要

示例：

```json
{
  "episodeId": 2001,
  "summary": [
    {
      "type": "SHOT",
      "count": 60,
      "status": "SUCCESS"
    },
    {
      "type": "CHARACTER",
      "count": 90,
      "status": "SUCCESS"
    },
    {
      "type": "DIALOGUE",
      "count": 0,
      "status": "NOT_STARTED"
    }
  ]
}
```

注意：

- count 为素材数量，不是角色数量。
- `NOT_STARTED` 属于素材提取状态，不是 AI 任务状态。
- 素材数量必须查询真实数据库。
- 不支持的类型应明确返回 `UNSUPPORTED`。
- 不能将没有数据直接判断为失败。

### 素材详情

所有素材至少关联：

```text
projectId
episodeId
assetId
assetType
createdAt
```

根据素材类型扩展：

分镜：

```text
shotId
startMs
endMs
frameUrl
```

人物：

```text
characterId
shotId
timestampMs
imageUrl
```

对话：

```text
speakerId
text
startMs
endMs
audioUrl
```

背景：

```text
sceneId
shotId
imageUrl
isCharacterRemoved
```

音频：

```text
audioType
startMs
endMs
audioUrl
```

剧情：

```text
eventId
startMs
endMs
description
characterIds
```

不能将所有类型强行塞入一个包含大量无意义空字段的数据库实体。


要求：

2. 不直接修改已执行过的 Flyway 历史脚本。
3. 使用新的版本化迁移脚本。
4. 统一索引和外键策略。
5. 任务与素材关联清晰。
6. 支持同一剧集多次提取。
7. 支持任务重试。
8. 支持素材版本或重复生成结果管理。
9. 不允许任务重试时重复插入相同素材。
10. 保留原始视频记录。

必须记录关键业务日志：

- 视频上传开始和结束
- MinIO 上传结果
- AI 任务创建
- RabbitMQ 投递
- RabbitMQ 消费
- Python 调用
- Python 返回结果
- 素材持久化
- 任务状态变更
- 任务失败与重试

日志字段尽量包含：

```text

taskId
projectId
episodeId
extractType

```

不要在日志中输出：

- JWT
- 密码
- MinIO SecretKey
- 用户敏感信息
- 完整的大体积视频或图片数据

接口调用日志应有合理的脱敏与大小限制。

## 十二、Java 开发规范

必须遵守：

1. 不使用 `var`，全部使用明确类型。
2. 关键业务逻辑添加中文注释。
3. 重要接口和流程添加日志。
4. 遵守 IDEA Java 格式化规范。
5. 长方法调用合理换行。
6. Controller 不编写复杂业务逻辑。
7. Service 负责业务编排。
8. Mapper 负责数据库访问。
9. DTO、VO、PO 分离。
10. 使用 MyBatis-Plus，不使用 JPA。
11. 统一异常处理。
12. 统一响应结构。
13. 不使用魔法字符串表示任务状态。
14. 不随意引入新框架。
15. 不生成无意义的工具类。
16. 优先复用已有模块。
17. 不破坏现有接口兼容性。
18. 重要状态变更必须具有事务边界。
19. 不在数据库事务中长时间等待 Python 推理。
20. 不允许静默吞掉异常。

## 十四、验收标准

完成后需要验证：

1. 视频可以正常上传到 MinIO。
2. 视频元数据保存成功。
3. 关闭自动提取时不会创建任务。
4. 开启自动提取时自动创建任务。
5. 不支持的提取类型会被拒绝。
6. 上传成功后立即返回任务 ID。
7. RabbitMQ 可以正常投递任务。
8. Java 能调用现有 Python 服务。
9. 已实现的分镜和人物提取功能可以正常运行。
10. AI 任务状态可以查询。
11. 任务失败可以重试。
12. 素材库可以查询真实素材。
13. 不会重复创建相同任务。
14. 服务重启后任务不会无故丢失。
15. 已有数据不受破坏。
16. Maven 构建通过。
17. 关键接口测试通过。

如果 Python 服务没有运行或接口尚未实现，应明确报告未完成的联调项目，不能将模拟结果当作真实成功。
