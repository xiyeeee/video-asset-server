# 素材提取任务设计

主任务 `ai_extraction_job` 绑定项目、剧集和具体原视频。每个类型占一个 `ai_extraction_step`。
步骤关联既有 `ai_task` 执行记录。素材由 Java AI 事务提交到公共 `asset` 表，Media 按权限读取和签发预览。
数据库视图从步骤及执行任务推导主状态，列表可按该状态过滤。

## 投递与恢复

1. Media 或 AI 将主任务、步骤一起写入数据库。提交之后，Java AI 扫描到期主任务并尝试 RabbitMQ 发送。
2. RabbitMQ 使用 `video.asset.ai` 交换机和 `video.asset.extraction.job` 持久队列。发送以确认和退回消息判断。
   未确认短间隔重投，积压任务低频补投。连续失败达到五次或总投递超过三十分钟时结束为投递失败。
3. 消费者按主任务行加锁，只为未关联的步骤分配执行任务。脚本崩溃、结果回滚和重复消息都可恢复。
   已关联的步骤在独立的执行租约下调度，Python 运行时数据库事务已结束。
4. Java HTTP 提交超时先查原执行 ID。Python 明确查无任务时用原参数恢复，最多三次提交。
   已收到结果时先在执行任务记录保存结果引用，再导入 MinIO 与数据库。分镜、音频和人物均以同一次 Python 发布内容重放。
5. 重试只解绑失败步骤。成功步骤保留并继续可查询。无进度百分比的步骤返回阶段或 `null`。
   已发布对象写入成功而数据库未提交时，下一次导入写同一个对象键。无活跃任务引用的未绑定对象可按部署留存策略清理。

目前按类型分配独立处理器。当上游有必要产物可以复用时，通过步骤引用和同源结果查找实现。
未来若人物协议支持消费已有分镜帧、对白协议支持消费音轨，可在分配相关步骤前检查依赖是否完成。
显式再生成时使用新的执行记录及对象版本，通过 `sourceTaskId` 可查看旧版。

分镜先完整校验 v1 清单和所有 JPEG。对象键固定到执行任务 ID 与镜头索引，正式分镜和步骤成功在同一数据库事务发布。
分页默认使用当前原视频的最新成功版本，并可通过 `sourceTaskId` 固定在旧版。

Gateway 日志可按网关 traceId 检索请求。Media 记录上传和建单，Java AI 记录消息、Python 调用、导入和失败。
主任务通过消息消费日志的 `sourceTaskId` 关联 Python 执行 ID。以下命令使用实际日志路径和标识。

```bash
rg -F 'traceId=<网关请求标识> ' gateway.log
rg -F 'taskId=792 ' ai.log
rg -F 'taskId=922 ' ai.log
```
