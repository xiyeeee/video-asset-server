\# video-asset-server｜对接 Python 人物提取服务\
\
在现有 video-asset-server 仓库中实现人物提取的业务闭环。先阅读 AGENTS.md、现有剧集和上传流程，以及 Python 交付的 docs/java-character-extraction-api.md 和实际 characters.json。以 Python 的实际协议为准。复用已有鉴权、存储、MyBatis-Plus 和响应结构，缺少的部分只补本轮需要的最小实现。\
\
1\. 为已上传的剧集视频提供人物提取入口。校验当前用户对剧集的操作权限，由 Java 生成并保存业务 taskId，再提交给 Python。通过配置管理 Python 的服务地址、连接和读取超时及共享目录。\
2\. 后台轮询 Python 状态并同步到 Java。Python 提交超时时，沿用原 taskId 查询或重试，避免重复推理。短暂通信失败与 Python 明确返回 FAILED 分开处理。结合实际协议处理 Python 重启后查不到任务的情况，避免任务一直挂在处理中。\
3\. Python 成功后，按对接文档解析并校验 characters.json 和素材引用，将人物素材关联到对应剧集和任务。素材保存与 Java 成功状态保持一致，重复同步同一任务不得重复入库。零素材正常完成。同帧多人的素材分别存储，帧内编号不得作为跨帧唯一标识。\
4\. 提供前端可调用的发起提取、查询任务、按剧集查询人物素材接口。素材至少返回可访问的预览或下载地址、timestampMs 和稳定的素材 ID。素材访问沿用项目鉴权和文件存储机制，使用浏览器可访问的地址。\
5\. 遵守 Java 开发规范。使用显式类型，不使用 var。关键流程写简洁中文注释，复杂参数和调用按 IDEA 格式换行。区分 DTO、VO 和持久化实体。记录 Java 到 Python 的提交、轮询和结果导入日志，包含 taskId、耗时以及状态或错误码。\
6\. 输出 docs/frontend-character-extraction-api.md，写清触发入口、接口路径、鉴权、请求响应示例、状态枚举、轮询结束条件、空结果、失败重试、图片访问方式和 timestampMs 的单位。\
7\. 用真实 Python 服务和短漫剧联调。验收从 Java 发起任务，最终从 Java 接口查到能打开的透明 PNG 和实际帧时间戳。再验证重复同步不会增加素材记录。汇报真实联调与模拟验证结果。\
\
