# v1.0.5 前端对接任务 · 视频首帧解析

在当前前端仓库中，接通上传完成后的「开始解析 → 任务状态 → 素材库首帧分镜」。先读取仓库 `AGENTS.md`、现有解析页和素材库实现，复用已有路由、页面组件、API 客户端、认证和查询缓存。项目、集数与原视频预览继续使用 Media 接口。

## 接口与类型

完整后端契约见 [首帧解析 API](../analysis-api.md)。本地 Gateway 为 `http://127.0.0.1:18080`，下表前缀为 `/api/ai/v1/projects/{projectId}/episodes/{episodeId}`。业务请求通过现有客户端携带 Bearer Token，解包 `Result<T>` 的 `data`。

| 方法 | 路径后缀 | 响应 `data` |
| --- | --- | --- |
| GET | `/analysis` | `AnalysisTask \| null` |
| POST | `/analysis` | `AnalysisTask`，空请求体，接受 `200` 和 `202` |
| POST | `/analysis/{taskId}/retry` | `AnalysisTask`，空请求体，接受 `200` 和 `202` |
| GET | `/frames` | `FramePreview[]` |

```ts
type AnalysisTask = {
  id: string;
  episodeId: string;
  status: 'PENDING' | 'RUNNING' | 'SUCCEEDED' | 'FAILED';
  attemptCount: number;
  errorCode: string | null;
  resultAssetId: string | null;
  createdAt: string;
  startedAt: string | null;
  finishedAt: string | null;
};

type FramePreview = {
  id: string;
  name: string;
  type: 'storyboard';
  timestampMs: number;
  sizeBytes: number;
  url: string;
  expiresInSeconds: number;
};
```

## 页面行为

1. 选择已上传的集数后查询当前任务。`null` 时显示「开始解析」。提交按钮在请求过程中禁用，提交完成后使用返回的任务状态。提交请求超时可重新查询或再提交，服务端按集数复用任务。
2. `PENDING` 显示「等待解析」，`RUNNING` 显示「正在提取首帧」。仅这两种状态每 2–3 秒查询一次。页面离开、项目或集数切换、进入终态时停止当前轮询。以项目和集数作为查询缓存键，切换账号时沿用现有会话缓存清理。刷新页面通过 GET 恢复状态。本期展示状态与阶段，界面进度来自接口。
3. `FAILED` 时基于 `errorCode` 展示简短说明，并提供「重试」。重试使用原 `taskId`，以响应更新状态。HTTP 错误继续交给现有认证和错误处理。区分状态查询失败与任务执行失败。
4. `SUCCEEDED` 后立即刷新该集分镜查询，素材库按当前集展示真实图片。打开素材库时也可直接查 `/frames`，空数组显示当前集还没有分镜。将签名 URL 直接用于 `<img src>`，通过重新查询处理签名过期或加载失败。签名 URL 仅用于即时预览，经会话缓存管理，避免写入持久化存储或日志。

## 联调验收

- 使用有权限的项目和已上传 MP4，首次查询返回 `null`，提交后显示真实状态，成功后看到一张可打开的首帧截图。
- 连续提交、刷新或离开页面再回来，得到相同任务 ID。切换集数后状态和截图跟随该集。
- 使用 Mock 响应或后端提供的失败任务，验证错误提示、重试和重新取图。准备一例 `401` 或 `404` 验证现有认证和页面错误处理。
- 按仓库规范只检查受影响的页面、类型和 API 请求模块。
