# 视频转素材平台 — Spring Cloud 后端基础架构初始化

## 一、项目背景

正在开发一个「AI 视频转游戏素材平台」。

用户可以上传 AI 漫剧视频（通常每集约 2 分钟），并上传对应原著小说作为参考资料。

未来系统通过 AI 自动提取：

1. 人物素材：角色截图、外观、表情、角色信息。
2. 对话数据：说话人、台词、时间戳。
3. 场景素材：背景图片、场景描述。
4. 剧情数据：剧情事件、人物动作、镜头信息。
5. 音频素材：角色语音、背景音乐。
6. 结构化数据：JSON、ZIP 素材包。

后续可能接入 Unity 和 Live2D，但当前阶段只开发视频转素材平台，不开发游戏功能。

整体架构：

- React + TypeScript：前端管理平台
- Spring Cloud：业务后端
- Python + FastAPI：AI 视频分析服务
- MySQL：业务数据
- Redis：缓存与任务状态
- RabbitMQ：异步任务消息
- MinIO：视频与素材文件存储
- Nacos：服务注册与配置管理

本轮只实现 Java 后端基础架构。

**video-asset-ai**

## 七、MySQL 与 Flyway 初始化

本轮允许创建基础数据库及初始化 SQL。

数据库名称：

`video_asset`

建议基础业务表：

```text
sys_user
project
video_episode
ai_task
asset
character
dialogue
scene
```

要求：

1. 使用 MySQL 8 兼容 SQL。
2. 默认字符集 `utf8mb4`。
3. 使用 Flyway 管理数据库迁移。
4. 初始化脚本必须可重复部署到全新环境。
5. 设计必要的主键、索引、唯一约束和外键策略。
6. 统一创建时间、更新时间等审计字段。
7. 不创建大量测试业务数据。
8. 不把真实账号密码写入 SQL。
9. 明确由哪个服务负责执行 Flyway 迁移，避免多个服务同时迁移同一数据库。
10. 不要求所有微服务共享同一套业务表的写入权限。

数据库结构应当适合未来的视频集数、角色识别、对话时间轴和素材管理。

本轮只建立初始表结构，不生成完整业务 CRUD。
