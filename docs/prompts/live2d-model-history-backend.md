你正在开发「视频转素材」项目的 Java 后端。请为现有 Live2D 生成链路补上模型包持久化、版本记录、历史查询、预览和下载。

先阅读现有生成任务、Python 或第三方生成服务对接、模型产物目录、项目与角色归属、存储和鉴权实现。用代码确认当前生成成功后返回了哪些文件或地址，以及它们能否在服务重启后继续访问。复用当前项目的持久化和文件存储设施，沿用现有 ORM、接口响应与异常处理规范。

一、生成成功后自动保存

1. 生成服务返回成功后，由后端保存完整模型包。保存范围包括模型入口文件及其引用的模型、贴图、物理、表情、动作等实际产物。按现有生成格式保存相对目录结构，确保历史预览能正确加载依赖。
2. 生成结果来自工作目录或临时链接时，将产物复制到项目已有的持久化存储。保存记录使用稳定的存储标识，预览地址和下载地址在查询时按现有方式提供。
3. 保存模型版本时关联项目、角色、生成任务或产物标识，记录版本号、保存时间、模型入口和模型包位置。产物具备缩略图或来源信息时一并保存。
4. 同一项目、同一角色下，真实的新生成结果产生新版本。按现有任务或产物标识对重复回调、重试做幂等处理。同一角色并发生成时，保证版本号唯一且历史顺序稳定。
5. 文件保存且必要产物可读取后，再将版本标记为可用，并向前端返回版本标识。保存失败时应提供明确状态，防止出现历史列表可见但无法预览或下载的记录。按现有机制处理重试与异常产物，优先复用仍可读取的生成结果。
6. 检查是否已有完整、可访问且归属明确的旧产物。符合条件时，根据实际情况纳入历史记录。对缺失或无法确认归属的旧产物，在交付说明中列出处理结果。

二、提供前端接口

接口路径和字段名沿用仓库已有命名；缺少同类接口时补齐。前端需要以下能力：

1. 查询当前项目下有已保存模型的角色。返回角色 ID、名称、头像以及最新版本标识（可用时）。
2. 查询指定角色的模型历史。返回版本 ID、版本号、保存时间、可用状态和缩略图等，最新版本排在前面。
3. 查询指定版本详情。返回版本归属、Live2D 模型入口地址和加载依赖所需的信息。如果资源地址有有效期，重复查询可以取得有效地址。
4. 下载指定版本的完整模型包。沿用项目现有下载方式，返回可访问的下载响应或有效地址。
5. 生成任务查询或结果响应提供模型保存状态及已保存版本 ID，供前端实现「查看模型」。沿用当前任务协议并兼容已有调用方。

角色列表、版本列表、详情、预览资源和下载均按现有鉴权方式核对用户、项目、角色及版本的归属。接口文档写清真实路径、请求参数、响应示例、状态含义和错误码，并说明前端怎样从生成结果定位历史版本。

三、代码规范与验收

1. Java 使用显式类型，禁止 var。沿用项目的 DTO、VO、持久化对象及 IDEA 格式规范。
2. 在保存、幂等处理、失败恢复等关键逻辑处写必要的中文注释。复用现有接口调用记录机制，记录任务 ID、项目 ID、角色 ID 和版本 ID，便于定位生成成功但保存失败的问题。
3. 验证同角色连续生成两次、同角色并发生成、重复回调、保存失败后重试、重启服务后访问历史、旧版本预览与下载，以及跨项目访问被拒绝。
4. 交付时列出实际修改文件、接口文档位置、数据库迁移或存储配置变更（如有）及联调结果。用实际请求验证历史预览和下载都能在独立于生成任务的情况下工作。
