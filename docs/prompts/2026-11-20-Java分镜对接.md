# Java 分镜任务和素材导入开发提示词

在 `video-asset-server` 接入正式分镜提取。先阅读仓库 `AGENTS.md`、`docs/extraction-workflow.md`、`docs/frontend-extraction-api.md`、现有任务、资产查询和导入代码，并保留工作区已有改动。跨端契约由同级 Python 仓库维护，读取 `../video-asset-ai/docs/shot-extraction-contract.md`。可以先用契约内的两镜头清单和模拟 Python 响应开发，随后用真实产物联调。

## 实现范围

1. 接入已有任务中心和上传自动提取的 `SHOT` 类型，沿用权限、发布、幂等、步骤重试和能力开关。调用统一 Python 接口并将该步骤映射到 `outputs:["SHOTS"]`，只读取对应分支状态和结果。共享目录、Python 地址和超时沿用现有配置。部署确认 Python 支持后，在 Media 和 Java AI 同步启用 `EXTRACTION_SUPPORTED_TYPES`。
2. 按契约校验 `shots.json` 版本、镜头数量、时间覆盖、实际代表帧时间和图片引用。上传缩略图到现有素材存储，写入可稳定定位镜头及执行版本的数据。沿用现有表和迁移机制，根据真实 schema 决定字段落点，兼容已有首帧记录。重复导入保持对象键和数据库记录幂等；验证缺项、非法路径或图片缺失不会发布半套分镜。
3. 扩展现有 `GET /api/media/episodes/{episodeId}/assets?type=SHOT` 和摘要读取，返回契约字段及签名 `frameUrl`，正式分镜同版本按 `shotIndex` 升序，支持 `sourceTaskId` 固定版本与分页。保证失败重跑仍可查到旧成功版本，兼容历史首帧和现有首帧 API。
4. 对外调用使用契约中完整网关路径。更新本仓库的前端提取 API 和部署文档，记录正确的 19000 端口和能力开关。使用任务 ID、步骤 ID、Python 请求 ID 关联日志，Java 步骤成功以完整导入为准。

## 验证

- 定向验证成功导入、无切点的一镜头、非法路径、清单不一致、重复导入、分页顺序和历史首帧回读。验证其他步骤成功时分镜失败仍可独立重试。
- 用真实 Python 清单验证导入及素材查询，检查镜头起止、代表图、最新成功版本和数据归属。分别汇报模拟和真实联调结果。发现字段或路径差异时回报给契约维护者。
