负责 video-asset-server，结合共享约定实现动作资产管理、版本、兼容性查询及剧情引用所需的数据接口。使用仓库现有 Spring Boot、MyBatis-Plus、数据库迁移、鉴权和存储方案。

一、持久化和版本

1. 先核对已有 Live2D 模型、模型版本、动作和项目资产表，复用已有结构。持久化基础动作、组合反应、版本、片段引用、模型版本能力映射，以及兼容性计算需要的数据。
2. 将共享约定中的完整目录和 20 个组合做成幂等初始数据。官方动作使用稳定编码，重复初始化不会产生重复项。用户编辑预设时，可以另存为自定义动作。
3. 编辑草稿和发布版本采用项目现有版本机制。已发布的组合固定引用基础动作版本，剧情固定引用组合版本。发布一个新版本后，旧剧情仍按旧版本播放。保存和发布时保证定义、轨道和引用的一致性。
4. 校验项目隔离、模型资产权限和引用完整性。归档时保留已被剧情使用的版本。对并发编辑使用项目现有的版本校验机制，返回前端可处理的冲突结果。

二、接口和业务规则

1. 提供动作分页查询、详情、草稿保存、另存、发布、版本查询、按模型版本查询兼容性，以及查看或更新模型能力映射的接口。支持类型、分类、关键词和模型兼容状态筛选。
2. 校验关键帧时间单调性、时长、幅度、方向、引用版本、片段替代规则。多个语义轨道可能映射到同一实际参数，兼容性检查应报告具体冲突参数和重叠区间。
3. 兼容性计算区分模型存在某参数、候选映射、已确认可播。组合缺少片段时按共享约定返回缺项和替代片段。涉及嘴部控制的语音交接，由前端播放器执行，后端描述出相关轨道和行为。
4. 将 Python 的模型能力识别结果接入现有任务或接口机制。模型资产版本变化时重新分析，对已有确认映射按实际资产版本管理。分析失败允许重试，保存明确的失败原因。
5. 有剧情模块时接入固定版本引用及对白偏移。剧情模块尚未落地时，输出可供联调播放器使用的引用示例。

三、工程交付

使用显式 Java 类型，不使用 var。按 IDEA 可读的方式换行，用 DTO、VO 和持久化对象表达各层数据。关键业务判断和事务边界写必要的中文注释。复用项目的接口调用记录与 traceId，记录动作 ID、模型版本、操作、耗时和失败原因。更新接口文档，给出正常、缺绑定、部分兼容和版本冲突示例。

验收：初始化可重复执行，保存后重启服务仍可查询组合及其版本。用两个绑定不同的模型版本请求同一组合，得到对应的兼容状态。发布基础动作新版本后，已发布组合仍能取到原引用版本。
