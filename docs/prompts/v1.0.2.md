## 后端

在 `video-asset-auth` 中实现以下 Gateway 接口，统一使用现有 `Result<T>`。

| 方法与路径 | 请求与行为 |
| --- | --- |
| `POST /api/auth/v1/email-codes` | `{email, purpose: "REGISTER"}`。发送注册验证码，返回 `retryAfterSeconds` |
| `POST /api/auth/v1/register` | `{email, username, verificationCode, password, confirmPassword}`。校验成功后创建账号，返回 `201` 和用户资料 |
| `POST /api/auth/v1/login` | `{account, password}`。`account` 支持邮箱或用户名，返回 `accessToken`、`tokenType`、`expiresIn` 和用户资料 |
| `GET /api/auth/v1/me` | 校验 Bearer JWT，返回当前有效用户资料 |

- 复用 `sys_user`、BCrypt 和 Auth 的 Flyway。通过新迁移增加邮箱、邮箱验证时间及唯一约束，兼容已有用户数据。用数据库唯一约束处理并发注册。
- 验证码使用安全随机生成的 6 位数字字符串，保留前导零。默认 5 分钟有效、60 秒重发冷却、最多 5 次错误尝试。同一邮箱重发后旧码失效。按邮箱和请求来源限流，登录失败也限流。
- 验证码以独立密钥生成 HMAC，绑定邮箱、用途和挑战 ID。发送 SMTP 在事务外执行。仅发送成功的挑战可以注册，创建用户与消费验证码在同一事务内完成。错误尝试计数须持久化，避免随注册失败回滚。
- Auth 使用与现有下游兼容的 RS256 签发 JWT，`sub` 使用内部用户 ID，签发者和受众沿用当前配置。私钥只注入 Auth，Gateway 转发 Bearer，各业务服务继续独立验签。
- 精确放行发送验证码、注册和登录三个公开接口。登录失败使用通用文案，区分限流、验证码无效和邮件服务不可用。验证码、密码、JWT、SMTP 凭证不进入响应日志或 Git。

## 真实邮件

使用 Spring Boot Mail 连接真实 SMTP，支持发件地址、授权码、连接超时以及 SSL 或 STARTTLS 配置。开发可使用独立的仓库外配置，生产由部署环境注入。

没有授权时，禁止读取或复用 FormaSpace 的 SMTP 凭证。测试邮件只发到明确批准的测试邮箱。SMTP 未配置或投递失败时，接口返回明确错误，前端显示可理解的提示。Mailpit 可以用于本地流程验证，真实收件箱收到验证码才算完成实际投递验收。

## 前端

- 实现 `/login` 和 `/register`，复用现有组件、表单校验和 API 封装。
- 注册页支持发送、倒计时、重发及错误反馈。修改邮箱后清空已输入的验证码。注册成功跳转登录页并预填邮箱。
- 登录成功后进入工作台或原先请求的站内页面。刷新时调用 `/me` 恢复会话。区分 Token 失效和网络故障，提供退出入口并清理用户相关缓存。
- 本期范围是注册、登录、邮箱验证和会话恢复。找回密码、第三方登录、Token 刷新和项目 CRUD 放到后续任务。

## 验收

1. 经 Gateway 发送验证码，获授权的真实邮箱收到邮件，用该验证码完成注册。
2. 同一账号分别使用邮箱和用户名登录，访问 `/me`，刷新页面后能恢复登录态。
3. 定向验证错码、过期、重发后旧码失效、验证码重复使用、重复注册、登录失败限流、无效 JWT 和 SMTP 失败。
4. 更新接口及本地邮件配置文档。交付时区分 Mock 或 Mailpit 验证、SMTP 接受投递、真实邮箱收件这三种结果。缺少凭证或收件确认时，如实说明尚未完成的验收项。
