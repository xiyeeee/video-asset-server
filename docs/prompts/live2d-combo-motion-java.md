你正在开发「视频转素材」项目的 Java 后端 video-asset-server。本轮负责组合动作的编译入口、保存和历史恢复。先阅读现有项目、角色、Live2D 模型版本、动作、文件存储、鉴权和 Python 调用代码，沿用仓库当前实现。

1. 定义组合动作数据
   组合动作关联 projectId、modelVersionId，保存名称、总时长、轨道类型、片段 ID、片段来源、起始时间和时长。单个动作与台词均使用稳定的素材 ID，已有版本机制时固定到对应版本。
   保存两类数据：可重新编辑的时间轴，以及对应的已编译播放产物。两者要对应同一份组合内容和模型版本。复用已有持久化方案。本轮延续项目当前的依赖和中间件范围，ORM 如已接入则沿用现有 MyBatis-Plus 规范。

2. 提供前端能力
   - 查询项目下可用的模型版本、单个动作和台词音频，优先复用现有接口。
   - 提交当前时间轴进行预览编译，调用 Python 并返回编译结果、播放资源、总时长、冲突或缺失能力。预览可以基于尚未保存的草稿。
   - 创建和更新组合动作。保存时校验已编译产物与当前时间轴和模型版本一致。草稿改过后需要重新编译，防止保存旧预览。重复提交按现有方式幂等处理。
   - 查询组合动作列表和详情。详情应支持直接重播以及恢复可编辑的轨道。返回稳定的组合 ID，供以后剧情节点引用。

3. 保证历史可恢复
   校验项目、模型版本、动作和音频素材的访问权限及引用关系。使用稳定存储标识保存播放产物，临时访问地址按需签发或刷新。文件可读取后再确认保存成功。历史组合始终打开保存时关联的模型版本。
   保存失败时保留可重试信息。保存成功后，即使关闭浏览器并重启服务，也能查询组合并取得播放资源。

   Java 使用显式类型，禁止 var。遵守现有 DTO、VO、PO 和 IDEA 格式规范。对编译、保存、重试和异常处理写必要的中文注释。沿用现有接口调用记录，串联 requestId、projectId、modelVersionId 和 comboId。
