# Java 对白任务和素材导入开发提示词

在 `video-asset-server` 接入对白提取。先阅读 `AGENTS.md`、`docs/extraction-workflow.md`、`docs/frontend-extraction-api.md`、现有任务同步、分镜清单导入与素材查询代码。三端契约位于同级仓库 `../video-asset-ai/docs/dialogue-extraction-contract.md`，按契约直接实现 Python HTTP 调用和正式导入。契约示例用于核对字段和独立测试，实际联调使用 Python 服务实时产生的清单。

## 实现范围

1. 复用任务中心、上传自动提取、权限、幂等和失败步骤重试，把 Java 的 `DIALOGUE` 映射到 Python 统一素材任务的 `outputs:["DIALOGUE"]`。读取该分支的阶段、`manifestRef` 和 `segmentCount`，包括零句成功。Python 部署可用后再同步启用 Media 和 Java AI 的能力开关。
2. 读取共享输出目录下的 `dialogue.json`，校验路径、版本、句数、半开时间区间、顺序和匿名编号，支持句段重叠。优先复用已存在的 `dialogue` 表，按现有迁移机制补齐执行版本、句段序号或匿名说话人信息。按执行版本和句段序号保证幂等，事务中完整导入并更新步骤成功。
3. 扩展摘要和 `GET /api/media/episodes/{episodeId}/assets?type=DIALOGUE`。按契约返回对白字段和 `sourceTaskId`，支持分页和固定版本，优先读当前原视频最新成功版本。验证失败重跑保留旧结果，最新成功零句返回空列表。首版 `characterId` 为空。
4. 更新前端 API、配置和错误码文档。复用任务、步骤和 Python 请求 ID 的日志关联。

## 开发与联调安排

本轮先完成代码和本端必要检查，按共用契约实现正式接口。三端各自开发，不等待其他端，不启动整链路联调。交付时汇报文件、现有检查结果、启动配置和后续联调入口。本端独立检查包括下列项目。

- 覆盖正常与零句导入、重叠段、未知说话人、非法相对路径、清单不一致、重复导入和分页版本。验证旧成功版本以及其他独立资产分支仍可用。

## 收到通知后集中验收

等用户确认三端都已完成开发，再执行下列真实联调。三端使用同一集带人声的原视频，测试示例仅用于字段核对和本端独立测试。

- 先核对 Python 已运行包含 `DIALOGUE` 的版本、真实模型已就绪、双方能读写同一共享目录。通过 Java 的 `POST /api/ai/tasks` 为已保存的真实剧集创建任务，观察 Java 步骤提交和轮询 Python、读取实时生成的 `dialogue.json`、持久化并返回素材。手工把示例写入共享目录或数据库不能作为验收。
- 向前端交接网关地址、实际 `episodeId`、Java 主任务 ID、Python 执行 ID、素材查询使用的 `sourceTaskId` 和真实返回的代表句段。对照 Python 清单，核对句段数量、顺序、时间和匿名说话人编号。
- Python 尚未就绪时，可以完成本端实现和独立测试，交付状态写「待真实联调」，列出需要的版本或环境配置。真实链路通过后再更新状态。
