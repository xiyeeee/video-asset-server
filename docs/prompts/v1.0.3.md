# 前端接入真实项目管理 API

在 `video-asset-web` 中完成登录后的项目管理联调。先检查前端 `AGENTS.md`、Git 状态、已有 API 封装、
TanStack Query、项目页面和设计稿，沿用现有技术栈和页面布局。本阶段验收目标是用户创建项目、刷新后仍能看到，并能查看和编辑其基本信息。

## 接口契约

开发通过现有 Vite 代理访问 Gateway `http://127.0.0.1:18080`，前端请求使用相对路径。
管理接口复用已有登录态的 `Authorization: Bearer <accessToken>`，响应沿用 `{code,message,data}`。
成功业务码为 `OK`。

| 方法 | 路径 | 入参 | 成功结果 |
| --- | --- | --- | --- |
| GET | `/api/media/v1/projects` | 可选 `q`、`page=1`、`size=20`，`size` 最大 100，`q` 最长 100 字符 | `200`，`data={items,page,size,total}` |
| POST | `/api/media/v1/projects` | JSON `{name,description}` | `201`，`data` 为项目 |
| GET | `/api/media/v1/projects/{projectId}` | 用字符串传项目 ID | `200`，`data` 为项目 |
| PATCH | `/api/media/v1/projects/{projectId}` | JSON，`name` 与 `description` 至少提交一个非空字段 | `200`，`data` 为更新后的项目 |

```ts
type ProjectSummary = {
  id: string
  name: string
  description: string
  createdAt: string
  updatedAt: string
}

type ProjectPage = {
  items: ProjectSummary[]
  page: number
  size: number
  total: number
}
```

创建时名称和简介均必填，去掉首尾空白后长度分别为 2–30 和 4–200 字符。编辑可以提交两个字段，
也可以只提交变更字段。缺省或 `null` 代表保持原值。列表按最近更新时间降序排列。
`400 INVALID_REQUEST` 显示校验提示，`401 UNAUTHENTICATED` 复用现有会话失效流程，
`404 NOT_FOUND` 显示项目不可访问或已不存在。历史空简介可能返回 `""`，详情正常展示空值。

## 前端实现

1. 在现有服务层增加项目请求模块和响应类型。检查 `src/features/auth/` 的会话、Bearer 注入及
   401 处理方式，复用已有机制。保持当前业务接口和 Mock 的调用边界。
2. `/projects` 使用真实分页查询。搜索名称或简介时重置页码，查询键包含搜索词和分页参数。
   覆盖加载、空列表、无搜索结果、失败重试和成功状态。
3. 复用 `ProjectFormDialog` 的现有样式和表单验证。创建成功后跳到服务端返回 ID 的
   `/projects/{id}`，更新项目列表。编辑成功后同步该详情和列表。待请求时防止重复提交；
   失败时保留用户输入并显示反馈。
4. 项目详情单独请求真实项目并展示基础信息和「暂无集数」。默认封面由前端兜底。
   检查 `AppShell` 是否仍通过 Mock 查询项目标题，并让真实项目详情使用真实名称。
5. 工作台的「新建项目」复用同一个真实写入入口。若同期接入工作台的「我的项目」及「项目总数」，直接使用真实列表和 `total`。解析进度、集数统计、素材、删除和上传暂不调用未实现的接口。已有演示页面不得把 Mock 数据关联到真实项目 ID。

## 验收

- 登录后可查看自己的项目。新账号显示空态，创建后进入详情，刷新仍能看到。
- 搜索、分页、编辑、失败重试和登录失效反馈正常。切换账号后清理上一会话的项目查询缓存。
- 用户 B 使用用户 A 的项目链接时显示通用 404。用户 A 仍能打开和编辑该项目。
- 按前端仓库的增量检查策略执行必要的 TypeScript、Oxlint 和实际联调，交付时列出实际结果。
